它把 Codex 变成什么

不是把消息简单转发给一个机器人，而是把本机真实的 Codex 会话映射成飞书里可管理、可恢复、可协作的远程工作台。

按项目组织工作

Bridge 从 Codex 历史会话和允许的目录中发现本地项目。选择项目后自动创建私有话题群，一个群只对应一个本地工作区。

按话题隔离会话

在项目群中新建一个飞书原生话题，就会创建一个独立 Codex 会话；也可以把历史会话恢复成话题继续，不需要接触任何 ID。

远程掌握执行过程

Codex 的回复、工具进度、关键里程碑和最终结果持续回到同一话题。状态卡支持手动刷新与自动同步，只更新卡片，不会刷屏或重新执行任务。

直接处理任务阻塞

当 Codex 等待批准或需要补充信息时，在飞书卡片里完成确认；也可以停止任务、追加要求并继续同一个上下文。

项目群 = 本地工作区一个目录一个私有群，项目边界清楚。
一个话题 = 一个 Codex 会话并行任务互不串线，重启后仍能恢复。
飞书 = 远程控制台看进度、做审批、补输入、继续追问。

这个公开页面由 GitHub Pages 静态托管，只提供项目说明和安装任务。它不接收 App Secret，不连接你的 Codex，不读取本机代码，也不代理飞书消息。

代码与 Codex 会话保留在用户设备，由本机 Codex 管理。
飞书 App Secret由 CLI 直接写入本机加密密钥库。
消息通道Bridge 主动建立飞书 WebSocket 长连接。
公开页面只承载介绍、GitHub 链接和可复制安装任务。

常见问题

先确认边界，再决定是否安装。所有核心实现都可以在公开仓库中审阅。

需要一台公网服务器吗？

不需要。Bridge 在你的电脑上运行，主动连接飞书长连接服务。开发机无需公网 IP、域名或入站端口。

页面上的按钮会直接创建飞书应用吗？

不会。按钮只复制安装任务给你的本机 Agent。真正的创建与授权通过本机 CLI 拉起飞书官方确认页完成，避免凭据经过介绍页服务器。

一个群里的多个任务会串线吗？

项目群中的每个飞书原生话题都绑定一个独立 Codex 会话。Bridge 会持久化话题与会话的映射，重启后可以继续。

安装时会申请哪些飞书能力？

主要用于收发话题消息、创建私有项目群、更新进度卡片、处理审批按钮，以及读取用户主动发送的文件。飞书官方确认页会展示完整差异，只有用户确认后才生效。

谁可以控制我的本机 Agent？

Bridge 支持用户、群聊和管理员白名单。正式使用前应限制飞书应用可用范围，并在本机配置最小必要的项目目录。
